# Coding Conventions

**Analysis Date:** 2026-10-14

Renci is a two-app monorepo: a Python 3.12 FastAPI backend in `apps/api/` (SMS/email agent built on Gemini via `google-genai`) and a SvelteKit 2 + Svelte 5 + Tailwind 4 frontend in `apps/web/`. Conventions below are split by app. No project skills directory (`.claude/skills/`, `.agents/skills/`) exists.

## Naming Patterns

**Files (API, `apps/api/`):**
- `snake_case.py` module names, grouped into feature packages: `sms/twilio_handler.py`, `email_channel/poller.py`, `agent/actions/ppp_data.py`.
- Every package has an empty `__init__.py` (e.g. `apps/api/agent/__init__.py`, `apps/api/tests/__init__.py`). Keep them empty.
- Packages are named by channel/domain, not layer: `sms/`, `email_channel/`, `agent/`, `language/`, `db/`, `routes/`, `models/`, `integrations/`.
- Do not name a package after a stdlib module (the email package is `email_channel/` precisely to avoid shadowing `email`).

**Files (Web, `apps/web/src/`):**
- Svelte components are `PascalCase.svelte`: `apps/web/src/lib/components/ChatWidget.svelte`, `AgentToggle.svelte`, `apps/web/src/lib/templates/DefaultTemplate.svelte`.
- SvelteKit route files follow framework names: `+page.svelte`, `+layout.svelte`, `[slug]/+page.server.ts`.
- i18n locale files are named by BCP-47 tag: `apps/web/src/lib/i18n/en.json`, `zh-Hans.json`, `zh-Hant.json`.

**Functions:**
- Python: `snake_case`. Verb-first: `get_business`, `create_owner`, `update_business`, `parse_incoming_sms`, `detect_language`, `send_email_reply`.
- Private/module-internal helpers are prefixed with `_`: `_get_client()` in `apps/api/agent/core.py`, `_load_data()` / `_naics_label()` in `apps/api/agent/actions/ppp_data.py`, `_handle_name()` ... `_handle_email()` and `_welcome_message()` in `apps/api/agent/actions/registration.py`, `_fetch_emails_sync()` in `apps/api/email_channel/poller.py`.
- Response-template builders end in `_response`: `help_response`, `status_response`, `hours_updated_response` in `apps/api/agent/prompts/templates.py`.
- Gemini tool functions use descriptive verb phrases the model can understand: `update_business_hours`, `lookup_ppp_data`, `compare_ppp_by_industry`, `extract_menu_from_photo`.
- TypeScript/Svelte: `camelCase` (`buildSmsEmail`, `sendMessage`, `fetchStatus`, `sortedHours`).

**Variables:**
- Python: `snake_case` locals; `UPPER_SNAKE_CASE` module constants (`TOOLS`, `STEPS`, `BUSINESS_TYPES`, `NAICS_LABELS`, `CARRIER_GATEWAYS`, `SMS_EMAIL_PATTERN`).
- Module-level mutable singletons are `_`-prefixed: `_client` (`apps/api/db/firestore.py`), `_df` (`apps/api/agent/actions/ppp_data.py`), `_running` / `_executor` (`apps/api/email_channel/poller.py`).
- Svelte: `camelCase` with `$state(...)` runes (`isActive`, `isLoading`, `ownerPhone`); `UPPER_SNAKE_CASE` for constants (`API_URL`, `CARRIER_GATEWAYS`).
- Firestore document fields and JSON keys are `snake_case` (`registration_step`, `business_id`, `description_en`, `name_zh`). Frontend types mirror these snake_case keys (see `interface Business` in `apps/web/src/lib/templates/DefaultTemplate.svelte`).
- Bilingual field pairs use `_en` / `_zh` suffixes: `description_en`, `description_zh`, `name` / `name_zh`.

**Types:**
- Python classes `PascalCase`: `Settings`, `IncomingSMS`, `IncomingEmail`, `BusinessProfile`, `MenuItem`, `Owner`, `EmailMessage`.
- TypeScript types `PascalCase`: `Locale` in `apps/web/src/lib/i18n/index.ts`, `Business` interface.

## Code Style

**Formatting:**
- No formatter configured (no `ruff`, `black`, `prettier`, `.editorconfig`, or pre-commit config anywhere in the repo).
- Python: 4-space indentation, double-quoted strings, PEP 8 style, two blank lines between top-level definitions. Lines occasionally exceed 100 chars (e.g. TwiML line in `apps/api/routes/webhooks.py:18`, patch chains in `apps/api/tests/test_registration.py`).
- Trailing commas in multi-line call/collection literals (see `IncomingSMS(...)` calls and `TOOLS` list).
- Multi-line user-facing strings use implicit string concatenation inside parentheses (`apps/api/agent/actions/registration.py:43-48`, `apps/api/agent/prompts/templates.py`), not triple-quoted strings. Triple-quoted f-strings are used only for system prompts (`apps/api/agent/prompts/system.py`).
- Svelte/TS: 2-space indentation, single quotes, semicolons (`apps/web/src/routes/+page.svelte`, `ChatWidget.svelte`, `AgentToggle.svelte`, `i18n/index.ts`). Exception: scaffold files generated by `sv create` use tabs (`apps/web/src/routes/+layout.svelte`, `svelte.config.js`, `package.json`). Use 2 spaces for new hand-written files.
- Styling is Tailwind utility classes inline in markup; brand red is hardcoded as `#D4382C` (`apps/web/src/lib/templates/DefaultTemplate.svelte`, also the default `theme.primary_color` in `apps/api/db/firestore.py` and `apps/api/models/business.py`).

**Linting:**
- Python: none.
- Web: only type checking via `svelte-check` (`npm run check` in `apps/web/package.json`). `tsconfig.json` has `"strict": true`, `checkJs: true`.
- Svelte 5 runes mode is forced for all project files via `compilerOptions.runes` in `apps/web/svelte.config.js`. Use `$state`, `$props`, `$effect`, `{@render children()}`; do not use legacy `export let` / `$:` syntax.

## Import Organization

**Python order (observed, not enforced):**
1. Stdlib (`import os`, `import re`, `import asyncio`, `from datetime import ...`)
2. Third-party (`from fastapi import ...`, `from google import genai`, `import pandas as pd`)
3. Local absolute imports (`from config import settings`, `from db.firestore import get_business`)

Groups are usually not separated by blank lines and order is not strict (e.g. `apps/api/db/firestore.py` imports `google.cloud` before `datetime`/`re`).

**Python path style:**
- All local imports are absolute from the `apps/api/` root (`from agent.actions.registration import handle_registration`). There are no relative imports. Tests and `uvicorn main:app` must be run with `apps/api/` as the working directory.
- Deferred (function-local) imports are used to break import cycles and to make optional/heavy modules lazy: `email_channel.poller` inside `apps/api/main.py` lifespan and `apps/api/routes/webhooks.py` handlers; `HTTPException` inside `apps/api/routes/api.py`. Use deferred imports only for these reasons.
- When mocking, patch the name where it is looked up (e.g. `agent.actions.registration.get_owner_by_phone`), which works because modules use `from x import name`.

**Web path aliases:**
- `$lib` -> `apps/web/src/lib` (SvelteKit default), e.g. `import ChatWidget from '$lib/components/ChatWidget.svelte'` in `apps/web/src/routes/+layout.svelte`.
- `./$types` for generated route types in `+page.server.ts`.

## Error Handling

**Patterns:**
- **Agent tools return status dicts, never raise.** Every Gemini tool returns `{"status": "success" | "error", "message": str, ...}` (`apps/api/agent/tools.py`, `apps/api/agent/actions/ppp_data.py`, `apps/api/agent/actions/photo.py`). Follow this shape for new tools; "no data" cases return `status: "success"` with an explanatory `message`.
- **User-facing fallbacks instead of exceptions.** `dispatch()` in `apps/api/agent/core.py` returns an error string when the business is missing and falls back to `help_response(language)` when Gemini returns no text.
- **Validation re-prompts.** Registration steps return a re-prompt string on invalid input rather than raising (`_handle_type`, `_handle_email` in `apps/api/agent/actions/registration.py`).
- **Lookups return `None`.** Firestore getters return `dict | None` (`get_business`, `get_owner_by_phone`, `get_business_by_slug` in `apps/api/db/firestore.py`); callers check for `None`.
- **HTTP 404 via `HTTPException`** in REST routes (`apps/api/routes/api.py`); the SvelteKit loader maps a non-OK response to `throw error(404, ...)` (`apps/web/src/routes/[slug]/+page.server.ts`).
- **Broad `except Exception` in background/IO paths.** Used in `apps/api/email_channel/poller.py` (logged), `apps/api/main.py` lifespan (logged), `apps/api/email_channel/receiver.py` header/body decoding (silently defaulted), and `apps/api/agent/core.py` MMS download (`pass`). When adding new background code, catch broadly but always `logger.error(...)`; do not add new silent `pass` handlers.
- **Frontend:** `try { ... } catch { ... }` with a user-visible fallback message or retained state (`ChatWidget.svelte`, `AgentToggle.svelte`).

## Logging

**Framework:** stdlib `logging`, configured once in `apps/api/main.py` with `logging.basicConfig(level=logging.INFO)`.

**Patterns:**
- Logger names are dotted under `renci`: `logging.getLogger("renci")` in `apps/api/main.py`, `logging.getLogger("renci.email_poller")` in `apps/api/email_channel/poller.py`. Use `logging.getLogger("renci.<module>")` in new modules.
- Messages use f-strings: `logger.error(f"Failed to fetch emails: {e}")`.
- `info` for lifecycle events (poller start/stop, per-email processed), `warning` for skipped optional features, `error` for caught failures.
- Most modules (agent, sms, db, routes) do not log at all. No structured/JSON logging.
- Frontend: no logging.

## Comments

**When to Comment:**
- Every Python module starts with a one-line docstring describing its role (`"""Agent core — dispatches SMS messages via Google ADK with Gemini."""`). Exceptions are a few small modules (`config.py`, `db/firestore.py`, `sms/*.py`, `routes/*.py`). Add a module docstring to new files.
- Inline comments explain intent/why: `# Delay first poll so uvicorn responds to Cloud Run health check` (`apps/api/email_channel/poller.py:49`), `# Append NYC defaults if not specified` (`apps/api/agent/actions/registration.py:89`).
- Section dividers in longer modules: `# --- Owner operations ---` in `apps/api/db/firestore.py`.
- Svelte markup uses HTML comments as section headers (`<!-- Header -->`).

**Docstrings:**
- One-line docstrings on public functions and route handlers (`"""Twilio SMS webhook — receives all incoming messages."""`).
- **Gemini tool functions MUST use Google-style docstrings with an `Args:` section.** The `google-genai` SDK builds the function-calling schema from the signature and docstring (`apps/api/agent/tools.py` module docstring). The first line says what the tool does; the following sentence says *when* the model should use it. Example from `apps/api/agent/tools.py`:

```python
async def show_status(business_id: str = "", language: str = "en") -> dict:
    """Show the business profile status including website URL, hours, and contact info.

    Use when the owner asks about their profile, status, or current settings.

    Args:
        business_id: The business ID (injected by system).
        language: Response language (injected by system).
    """
```

- No JSDoc/TSDoc in the frontend.

## Function Design

**Size:** Small. Most functions are under 30 lines; the largest is `fetch_unread_emails` in `apps/api/email_channel/receiver.py` (~65 lines). Multi-step flows are split into one `_handle_<step>` function per step dispatched from a single entry point (`handle_registration`).

**Parameters:**
- Full type hints on Python parameters and returns using modern syntax (`dict | None`, `list[str]`, `AsyncClient | None`). One gap: `dispatch(message, owner: dict, business_id: str)` leaves `message` untyped (it is an `IncomingSMS`).
- Gemini tool functions: every parameter is a primitive (`str`) with a default (`""`, `"en"`), and system-injected context (`business_id`, `language`) is passed as trailing keyword parameters. Keep this shape so the SDK's schema generation works.
- Data passed between layers as plain `dict`s (Firestore documents) rather than the Pydantic models in `apps/api/models/`.

**Return Values:**
- Channel handlers return the reply text as `str` (`route_message`, `handle_registration`, `dispatch`).
- Tools return `dict` with `status`/`message`.
- DB writers return `None` or a new document id (`create_business -> str`).
- Responses are bilingual: functions accept `language: str` (`"en"` or `"zh"`) and branch with `if language == "zh": ... return <english>` (English is the default/fallthrough branch). Registration prompts embed both languages in one message.

**Async:**
- All route handlers, DB access, and channel handlers are `async def`. Blocking libraries are wrapped: IMAP runs in a `ThreadPoolExecutor` via `loop.run_in_executor` (`apps/api/email_channel/poller.py`). Note that `client.models.generate_content` in `apps/api/agent/core.py`, Twilio `client.messages.create` in `apps/api/sms/sender.py`, and GCS calls in `apps/api/integrations/storage.py` are synchronous calls inside `async def` functions.

## Module Design

**Exports:**
- Python modules expose plain functions and module-level singletons (`settings` in `apps/api/config.py`, `router` in each `apps/api/routes/*.py`). No `__all__`.
- Routers: one `router = APIRouter(...)` per file in `apps/api/routes/`, registered in `apps/api/main.py` with `app.include_router(...)`. Versioned REST routes use `APIRouter(prefix="/api/v1")`.
- Data classes: `@dataclass` for internal message envelopes (`IncomingSMS`, `IncomingEmail`); Pydantic `BaseModel` for request bodies and schema models (`EmailMessage` in `apps/api/routes/webhooks.py`, `apps/api/models/business.py`).
- Config: single `pydantic_settings.BaseSettings` subclass with lowercase fields mapped from env vars (`apps/api/config.py`); import as `from config import settings`.
- Channel adapters normalize input into `IncomingSMS` and call `sms.router.route_message` (email path in `apps/api/email_channel/handler.py` and `/webhooks/email`). New channels should do the same.
- Svelte: default-export components; `$lib/i18n/index.ts` uses named exports (`t`, `en`, `zhHans`, `zhHant`, type `Locale`).

**Barrel Files:**
- Not used in Python (`__init__.py` files are empty).
- `apps/web/src/lib/index.ts` is the empty SvelteKit placeholder; import components by full `$lib/...` path.
